# Payroll Approval Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Email a task-pay breakdown (summary + Excel) when a Kaitet task-pay Payroll Entry enters Pending Accounts, with per-farm packs for farm managers, and a "Download pay breakdown" button for a selected date range.

**Architecture:** A pure module (`payroll_pack_book.py`) turns plain rows into a pack (workers, detail, by-task, checks, totals), a workbook and email HTML, and is tested without a site. A thin Frappe module (`payroll_pack.py`) loads rows with SQL, hooks the Payroll Entry workflow, sends mail from a background job and serves the download. Two small JS files add the button to the Payroll Entry form and list.

**Tech Stack:** Frappe v16, hrms, openpyxl 3.1.5 (already in the bench env), unittest.

**Spec:** `docs/superpowers/specs/2026-10-23-payroll-approval-pack-design.md` (commit ba1a995)

## Global Constraints

- Only `company == "Kaitet Ltd."` entries with at least one slip whose Additional Salary has `ref_doctype = "Work Management Payment"`.
- Trigger: `workflow_state` changes **to** `"Pending Accounts"`. Never at other stages.
- The five existing "Payroll Entry - …" Notifications are not touched.
- Sender: `notifications@karenroses.com`.
- Subject: `Task pay for approval — <entry> — KES <total>`; resend prefix `Revised: `; farm packs `Task pay for approval — <entry> — <Farm> — KES <farm total>`; test sends prefix `TEST: `.
- Attachment: `Task-pay-<start>-to-<end>.xlsx`, farm packs `Task-pay-<start>-to-<end>-<Farm>.xlsx`.
- Sheets, in order: `Payrolls`, `Workers`, `Detail`, `By task`, `Checks`. Empty Checks sheet says `No problems found.`
- Days worked = distinct `Work Actuals Employee.work_date` per employee where `payment_ref` is one of the pack's WMPAYs and `count_in_payroll = 1`.
- Headline total = sum of slip WM component (Salary Detail amount whose `additional_salary` refs a WMPAY). Farm total = sum of that farm's line amounts.
- Email body has no per-worker table; rendered HTML must stay under 100KB.
- Farm managers come from `Work Management Settings.stage_approvers` with `stage_label = "Actuals: Farm Manager"` and a non-empty `scope`, enabled users only.
- New code lives in `work_management/` (top level), **never** in `work_management/api/` (generated by port_app).
- Commits authored ghost-mann, no Claude co-author line.
- Tests: `cd ~/vscodeProjects/work_management && PYTHONPATH=. ~/frappe-v16-bench/env/bin/python -m unittest discover -s work_management/tests -t .`

## Review Focus

- A worker whose lines span two farms: appears in both farm packs with only that farm's Detail lines, and their Workers row shows both farms. → Task 1 `test_a_two_farm_worker_appears_in_each_farm_pack_with_only_that_farms_lines`.
- A slip with no WM-linked Additional Salary (a worker paid with no work behind it): must show in Checks, not be silently dropped. → Task 1 `test_a_slip_with_no_work_is_a_check`.
- Text in names/tasks containing `&`, `<` or apostrophes: email HTML must escape it (www/Jinja does not autoescape; here we build strings). → Task 2 `test_names_are_escaped_in_the_body`.
- Resubmit after Rejected: second send is `Revised:`, not a duplicate first send. → Task 4 `test_second_send_is_revised`.
- Range download by a user who can read only some entries: refused, not filtered. → Task 5 `test_range_with_an_unreadable_entry_is_refused`.

**Interfaces:**
- Produces:
  - `build_pack(entries: list[dict], lines: list[dict], slips: list[dict], days_by_employee: dict[str, int]) -> dict`
    - `entries`: `{name, start_date, end_date, workflow_state}`
    - `lines`: `{wmpay, employee, employee_name, farm, task, block, work_from, work_to, days, qty, rate, amount, entered_by, fm_approved_by, hr_approved_by, gm_approved_by}`
    - `slips`: one row per (slip, WM additional salary): `{entry, slip, employee, employee_name, wmpay, wm_amount}`; a slip with no WM Additional Salary has `wmpay=None, wm_amount=0`.
    - returns `{"entries": [...], "workers": [...], "detail": [...], "by_task": [...], "checks": [...], "totals": {...}}`
      - `workers` rows: `{employee, employee_name, farms (sorted list), days_worked, tasks, wm_amount, slip_amount, difference, flag}`; sorted by first farm, then name.
      - `by_task` rows: `{farm, task, workers, days, qty, amount}`.
      - `checks` rows: `{employee, employee_name, kind, detail}`; `kind` ∈ `"no_work"`, `"amount_mismatch"`, `"two_slips"`.
      - `totals`: `{workers, man_days, slip_total, line_total, by_farm: {farm: {workers, days, amount}}}`; `man_days = sum(days_worked)`.
      - each `entries` row gains `workers` and `amount` (slip total for that entry).
  - `filter_farm(pack: dict, farm: str) -> dict`: same shape. Detail and by_task are limited to that farm, workers to those with a line on that farm, and checks to those workers. `totals.slip_total` = that farm's line total (the farm figure in the subject).
  - `farms_in(pack) -> list[str]` sorted.
